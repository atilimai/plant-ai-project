# data/splits

Train / validation / test assignment for the 54,305 colour images of PlantVillage,
made at the level of the **physical leaf**. Generated by

```bash
python -m src.data.prepare --config configs/data.yaml
```

and re-checked in CI by `python scripts/audit_manifest.py`.

| File | What it is |
|---|---|
| `manifest.csv` | One row per colour image: split, leaf group, evidence used for grouping, md5 |
| `leakage_audit.json` | Output of the audit (must say `"passed": true`) |
| `split_summary.json` | Image and group counts per split and per class |
| `grouping_calibration.csv` | Simulation that justifies the frame buffer (see below) |

Images are not in the repository. Only paths relative to `data/raw/plantvillage/` are.

## Why the split is made per leaf

PlantVillage has several photos of every leaf (different angles, re-shoots, crops of the same
frame, a time series over several days). If you split by image, almost every test image has a
sibling from the same leaf in the training set. We measured this on the images that have an author
leaf id:

| Split strategy | Test images whose leaf is also in train |
|---|---:|
| Random 80/20 by image | 99.8% |
| Stratified 80/20 by image (the previous baseline notebook) | 99.4% |
| Previous `train_split.csv` / `test_split.csv` (all three image variants mixed) | 99.98% |
| **This split** | **0** (audited), ≈0.00% estimated for images without leaf ids |

A model evaluated on a leaky split is partly graded on photos of leaves it has already seen, so the
number looks better than it is. See `docs/previous_state_audit.md`.

## How leaf groups are rebuilt

The dataset does not ship a clean leaf id. `src/data/grouping.py` combines every piece of evidence
with union-find, so two images connected by any evidence end up in the same group:

| Evidence | Images linked |
|---|---:|
| `leaf-map.json` from the dataset authors (camera file name → leaf number) | 41,099 |
| Same camera file name within a class (`RS_NLB 3932.JPG`, `RS_NLB 3932 copy.jpg`, `… copy 2.jpg` are crops of one frame) | 1,369 |
| Leaf number written in the name (`GHLB_PS Leaf 23.7 Day 13`: one leaf photographed on several days) | 107 |
| Byte-identical files (md5) | 21 pairs, already covered by the rules above |
| Nothing (singleton) | 11,730 |

The result is 19,950 groups (median 1 image, 75th percentile 4, max 33).

Two quirks of the leaf map worth knowing about:

* the Apple black rot sheet is called `Apple_Frogeye Spot` (same pathogen, different common name),
  so the lookup matches on crop when the class name does not match exactly;
* file names like `RS_HL 5529 1.JPG` are a second export of frame 5529, not frame 1.

## Images without an author leaf id

13,194 images have no leaf id: all four Corn classes, Squash powdery mildew, Tomato Target Spot,
Tomato mosaic virus, Grape healthy, and parts of Tomato late blight, Septoria, YLCV, healthy and
Strawberry leaf scorch. Treating them as singletons would leak, because neighbouring camera frames
are usually the same leaf. We tried two things that did not work before settling on the current rule:

* **Linking neighbouring frames that look alike** (ImageNet MobileNetV2 embeddings). Similarity does
  not separate "same leaf" from "next leaf": median cosine similarity 0.82 vs 0.73 with heavy
  overlap. A threshold either links everything or almost nothing.
* **Linking all neighbouring frames.** Frame numbers are nearly contiguous inside a class, so chains
  swallow whole classes (Corn common rust became a single group) and those classes cannot be split.
* **Fixed blocks of 100 frames.** Small classes ended up with 4-6 blocks, and three classes had no
  test images at all.

What we do instead (`src/data/splits.py`):

Four of those 13,194 have no frame number in the file name at all (a screenshot, a Flickr export),
so there is no sequence to cut and they go through the group split as singletons; the other 13,190
are handled as follows.

1. **Contiguous segments.** Each camera sequence (class + file-name prefix) is sorted by frame
   number and cut into one test segment (15%), one validation segment (15%) and train (70%),
   with a random rotation per sequence. That creates at most three boundaries per sequence
   instead of one every few frames.
2. **Frame buffer.** Any held-out image within 20 frame numbers of an image from a higher-priority
   split is moved to `excluded`. Priority is train > test > val: train is never touched, and
   validation gives way to test. The rule only applies to pairs where at least one image lacks
   an author leaf id.

Groups that do have leaf evidence go through `StratifiedGroupKFold` (20 folds: 14 train, 3 val,
3 test), which keeps per-class proportions within about half a percentage point.

### Choosing the buffer

We cannot measure leakage directly on images without leaf ids, so we measure it on the 41,111
images that have one: hide their ids, apply exactly the same contiguous-segment + buffer rule, and
use the hidden ids to count leaks (`src/data/calibration.py`, output in `grouping_calibration.csv`):

| Frame buffer | Held-out images dropped | Held-out images sharing a leaf with train | Test images sharing a leaf with val |
|---:|---:|---:|---:|
| 0 | 0.0% | 1.56% | 1.52% |
| 5 | 3.6% | 0.44% | 0.37% |
| 10 | 7.1% | 0.15% | 0.10% |
| **20** | **14.1%** | **0.00%** | **0.02%** |
| 30 | 20.7% | 0.00% | 0.02% |

Known leaves span at most 20 frame numbers in 99% of cases (median 3), which is consistent with the
table. We use 20.

## Resulting split

| | train | val | test | excluded |
|---|---:|---:|---:|---:|
| images | 38,011 | 7,516 | 7,770 | 1,008 |
| leaf groups | 13,996 | 2,414 | 2,639 | – |
| healthy share | 27.8% | 27.9% | 27.7% | – |

Every class appears in every split. Classes split by camera sequence lose part of their val/test
data to the buffer (e.g. Tomato mosaic virus: 261 / 16 / 37, 59 excluded), so their per-class
metrics have wider error bars; this is noted next to the results.

## Audit

`src.data.splits.audit_splits` checks that no value of any of these is shared between two splits:
`group_id`, author `leaf_key`, camera file name within a class, file md5; it also re-checks the
frame buffer from scratch and lists classes missing from a split. Current result:

```
Leakage audit: PASSED
  shared group_id / leaf_key / identifier_in_class / md5: 0 for every pair of splits
  frame-buffer violations: 0
```

`src.evaluation.evaluate` refuses to report test metrics unless `leakage_audit.json` says
`"passed": true`.

## manifest.csv columns

| Column | Meaning |
|---|---|
| `path` | `color/<class>/<file>` relative to `data/raw/plantvillage/` |
| `class_name` | PlantVillage folder name, e.g. `Tomato___Late_blight` |
| `split` | `train`, `val`, `test` or `excluded` |
| `split_rule` | `leaf_group` (StratifiedGroupKFold) or `camera_sequence` (contiguous segments) |
| `group_id` | Leaf group; all images with the same id share a split |
| `group_source` | First evidence that grouped the image: `leaf_map`, `camera_frame`, `named_leaf`, `singleton` |
| `leaf_key` | Author leaf id (`<sheet>:::<leaf number>`), empty if unknown |
| `md5` | MD5 of the image file, to detect silent dataset changes |
| `has_segmented` | Whether the background-removed copy exists (1,196 do not, mostly Corn common rust) |
