# artifacts

Everything the evaluation pipeline produces. Unlike the weights, these are committed: they are the
evidence behind the numbers in the README and the model card, and they are small.

```
artifacts/
├── reports/
│   ├── summary.md, summary.json          all runs side by side
│   └── <run>/
│       ├── history.csv, config.yaml      copy of the training log and resolved config
│       ├── failure_analysis.md/.json     error breakdown, Grad-CAM leaf focus
│       ├── gradcam_leaf_focus.csv        per-image focus measurements
│       └── <split>[_segmented]/          metrics.json, per_class_metrics.csv,
│                                         confusion_matrix.csv, predictions.csv, probabilities.npy
├── figures/<run>/                        confusion matrices, per-class F1, reliability,
│                                         training curves, Grad-CAM grids
└── sample_outputs/<run>/                 prediction gallery
```

Regenerate everything with:

```bash
python scripts/run_experiments.py            # train + evaluate + analyse + export
python -m src.evaluation.summarize           # just the summary tables
```

`predictions.csv` holds one row per test image (true class, prediction, confidence, probability of
the true class), which is what the failure analysis and the gallery are built from — and what
anyone re-checking our numbers would want.

What is kept, and what is not:

* per-image predictions and probabilities only for the **colour test split**, the numbers we
  report; the validation split and the background variants keep their metrics, per-class tables and
  confusion matrix, and their per-image output can be regenerated by re-running the evaluation;
* photo-heavy figures (Grad-CAM grids, galleries) as JPEG, charts as PNG — same information, about
  a tenth of the bytes, which keeps the repository reviewable.

Only artifacts from committed configs belong here; experimental runs stay local.
